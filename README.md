# Vityungr — сайт художника

Статический сайт на [Astro](https://astro.build). Шрифты локальные (Fraunces, Schibsted Grotesk через Fontsource), без Google Fonts.

Сейчас в проекте две версии главной:

| Версия | Адрес | Код |
|---|---|---|
| **Галерея** (основная): белый фон, ровные ряды картин, у каждого раздела заголовок и текст. Плавный скролл и появление написаны вручную; выезд картины снизу и просмотр — код прошлой версии на GSAP | `/` | `src/components`, `src/scripts`, `src/styles` |
| Прошлая, лендинг (в запасе): GSAP + Lenis | `/v1/` | `src/v1`, страница `src/pages/v1` |

Все работы в продаже — `/works` (`src/pages/works/index.astro`). На главной в Available now видно три ряда (`<Wall rows={3}>`), дальше кнопка на эту страницу. Первый экран — большое видео с приветствием и текстом, справа выбранная картина, внизу лента миниатюр (`src/components/home/Hero.astro`).

Каталог, фото и тексты у обеих общие. Чтобы убрать прошлую версию, удалите `src/v1` и `src/pages/v1`. После этого из `package.json` можно убрать `lenis` и `@iconify*` (`gsap` нужен галерее).

Сайт на двух языках: английский на корне (`/works`), русский — `/ru/…` (`/ru/works`). Подробнее — в разделе «Русская версия».

## Запуск

```bash
npm install
npm run dev      # http://127.0.0.1:4321
npm run build    # статика в dist/
```

### Как ведут себя картины

- Под каждой картиной всегда видно название.
- Навёл курсор — остальные картины гаснут до тонкого контура, наведённая чуть приподнимается, проявляются цена и размер. Одновременно она выезжает снизу краем на всю ширину экрана и покачивается.
- Первый экран: слева видео с приветствием, справа выбранная картина, она немного заезжает на видео. Наведение на миниатюру в ленте (тап на телефоне) — картина вылетает из ленты и ложится под небольшим случайным углом, прежняя гаснет. Сверху картина здесь не опускается (`data-hero-side` в `art.ts`).
- Картину под курсором определяет `scripts/art.ts` по координатам мыши, поэтому наведение не сбрасывается, пока страница едет.
- Клик — картина открывается почти на весь экран. Закрыть: Esc, клик мимо или «Close».
- На телефоне цена и размер видны сразу, картина открывается по тапу.
- Высота рядов задаётся в разделах (`<Wall height={…}>`), скорость скролла — константа в начале `scroll.ts`.

## Русская версия

- Адреса: английская страница `/x`, русская — `/ru/x`. Отдельных русских файлов страниц нет: `i18n.fallback` в `astro.config.mjs` собирает `/ru/…` из тех же страниц.
- Язык страницы компонент берёт из `Astro.currentLocale`: `const t = tr(langOf(Astro.currentLocale))`, дальше `t("Works", "Работы")` (`src/i18n.ts`). Длинные абзацы со ссылками — `lang === "ru" ? (…) : (…)`.
- Ссылки внутри русских страниц пишутся как обычно (`/works`); `/ru` к ним добавляет `src/middleware.ts`. Не трогает файлы, `/_astro`, `/api`, `/v1` и ссылки с `hreflang` (переключатель языка в шапке).
- Названия работ и принтов по-русски — `src/data/titles-ru.ts` (по английскому названию из каталога; чего нет — показывается как есть). Серии — `seriesRu` в `src/data/series.ts`, техника, статусы, размеры — функции в `src/lib/works.ts` с параметром `lang`.
- Новая работа в каталоге: добавьте её название в `titles-ru.ts`.
- Форма заявки отправляет `lang`: обработчик пишет Вите «Language: Russian» и без JS возвращает на `/ru/order/sent/`.
- Архив `/v1/` только английский: `/ru/v1/` переадресует на `/v1/`.

## Страницы работ и серий

- **Работа.** Слева фото. Если их несколько, под фото миниатюры. Клик открывает просмотр, снизу фото не выезжает: у него атрибут `data-art-still`, его пропускает `art.ts`. Справа статус, цена, кнопка заявки, техника, размер, год, серия и масштаб — картина рядом с листом A4 в одном масштабе. Какое из двух чисел размера — высота, решают пропорции фото: в каталоге порядок не всегда один. Если у работы есть история в `fieldNotes`, она тоже тут.
  - Работа в продаже: ниже форма заявки с уже выбранной картиной (`<OrderForm work={…}>`).
  - Продана или недоступна: вместо формы кнопка «Ask about a similar painting» ведёт на `/order?work=other&like=<название>`, сообщение подставится само.
  - Внизу другие работы серии, сверху «Prev / Next» по серии. Для поисковиков — разметка `VisualArtwork`, для превью ссылки в мессенджерах — `og:image`.
- **Серия.** Вступление из `series.ts`, блоки «Available now» и «Archive» (проданные и остальные), другие серии обложками. Порядок работ один и тот же здесь и в «Prev / Next» — `seriesOrder` в `src/lib/works.ts`.
- **New works** — работы, которые на старом сайте были только в «Available works» (серия `new` в каталоге). На главную эта «серия» не идёт.

## Принты

`/prints`: лимитированные партии (по 5 штук, остаток из каталога), открытый тираж, анимационные принты, внизу Print Club. «Request» под принтом открывает `/order?work=prints/<вид>/<папка>`. В форме принты идут отдельной группой. У открытого тиража выбирается размер (9 × 12 in — €30, A3 — €40), у «Swallow Island» — набор кадров. Варианты и цены — `src/data/prints.ts`, со старого сайта. Обработчик проверяет, что вариант из списка этого принта.

## Доставка и вопросы

`/shipping`: как устроен заказ (три шага) и вопросы по темам. Заказ — заявка без оплаты, упаковка вручную за 1–3 рабочих дня, США и Канада, условия принтов — со старого сайта (`/orderdelivery`, `/prints`, `/sale`).

**Черновики, сверить с Витей:** стоимость доставки оригиналов, бронь на время переписки, таможня (платит получатель), возврат (14 дней, обратную доставку оплачивает покупатель), что делать при повреждении.

## Заявки на картины

Оплаты на сайте нет. Покупатель выбирает картину на `/order` (или жмёт «Request this work» в просмотре — тогда `/order?work=<серия>/<папка>` откроется с выбранной работой), оставляет имя, почту, страну и ставит галочку согласия.

Дальше `public/api/order.php` на хостинге:

1. проверяет поля, ловушку для ботов и частоту (5 заявок в час с одного IP);
2. сохраняет заявку JSON-файлом в `vityungr/orders/` — рядом с `public_html`, из интернета не открывается. Хостинг в России, так первая запись данных делается в РФ (152-ФЗ). Файлы старше года удаляются сами — этот срок написан в политике;
3. шлёт заявку в Telegram и на почту (Reply-To — адрес покупателя, можно сразу отвечать).

Название и цену работы обработчик берёт из `api/works.json` (собирается из каталога, `src/pages/api/works.json.ts`), а не из формы. Без JS форма тоже работает: после отправки переход на `/order/sent/`.

Локально (`npm run dev`) PHP не запускается — отправка формы покажет ошибку. Проверять на хостинге.

**Telegram-бот:** создать у @BotFather, токен → секрет `ORDER_TELEGRAM_TOKEN`. Написать боту (или добавить его в группу), открыть `https://api.telegram.org/bot<токен>/getUpdates` и взять `chat.id` → секрет `ORDER_TELEGRAM_CHAT`.

## Персональные данные

`/privacy` — политика, `/consent` — согласие (отдельным документом, как требует 152-ФЗ с 01.09.2025). Обе страницы на английском и русском, русская версия главная. Ссылки на них в подвале, на согласие — в галочке формы; редакция согласия уходит вместе с заявкой.

Если меняется обработка данных (Метрика, рассылка, новые поля формы, другой хостинг) — поправить оба документа и дату `operator.effective`.

## Как обновляется каталог

1. `npm run scrape` — забирает работы, цены и фото со старого сайта на Тильде в `works/` (в git не идёт).
2. `npm run images` — обрезает белую подложку, уменьшает фото до 1600 px, пишет `src/assets/works` и `src/data/catalog.json`.

3. `npm run media:prepare` — собирает `media/vityungr/` для архива исходников в Selectel (бакет `websites-media`, папка `vityungr/`): `tilda/` — фото со старого сайта и каталог, `hires/` — исходники от Вити в полном размере. В git и на хостинг они не идут.

Веб-версии фото (`src/assets/works`) лежат в git, сайт собирается без внешних сервисов.

## Выкладка

Как у nicktmsh: пуш в `main` → GitHub Actions (`.github/workflows/deploy-hosting.yml`) собирает сайт и заливает `dist/` на Timeweb по SFTP (`.github/deploy-hosting.sh`, lftp mirror). `.htaccess` лежит в `public/` и попадает в `dist` при сборке.

В настройках репозитория (Settings → Secrets and variables → Actions):

| Что | Тип | Пример |
|---|---|---|
| `HOSTING_HOST` | variable | сервер Timeweb, `vh460.timeweb.ru` (тот же, что у nicktmsh) |
| `HOSTING_USER` | variable | логин хостинга |
| `HOSTING_DIR` | variable | `vityungr/public_html` (по умолчанию): папка сайта в Timeweb + `/public_html` |
| `HOSTING_PROTOCOL` | variable | `sftp` (по умолчанию) или `ftp` |
| `HOSTING_PASSWORD` | secret | пароль хостинга |
| `ORDER_TELEGRAM_TOKEN` | secret | токен бота для заявок |
| `ORDER_TELEGRAM_CHAT` | secret | id чата, куда бот шлёт заявки |
| `ORDER_EMAIL` | variable | почта для заявок, по умолчанию `vityungr.art@gmail.com` |
| `ORDER_MAIL_FROM` | variable | необязательно: отправитель писем, ящик на домене сайта (иначе `noreply@<домен>`) |
| `SITE_URL` | variable | необязательно: адрес сайта для ссылок в заявках, иначе берётся из запроса |

Секреты заявок `deploy-hosting.sh` пишет в `api/order-config.php` (`.github/order-config.mjs`), `.htaccess` закрывает этот файл от прямых запросов. Без Telegram-секретов заявки идут только на почту.

Пока `HOSTING_HOST` не задан, workflow только собирает сайт. Перезапустить вручную: Actions → Deploy to hosting → Run workflow.
